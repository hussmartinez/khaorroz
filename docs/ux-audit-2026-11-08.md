# Khaorroz — UI/UX audit (2026-11-08)

Method: Playwright 1.65 (Chromium) against the live site, iPhone-class 390×844 (touch) and 1440×900,
light + dark, en / ar (RTL) / es; axe-core WCAG 2.1 AA; LCP/CLS observers; 10 scripted journeys
(portal → section → switcher, filters + full-text search + `?q=`, cooking mode / checklist / timers,
language switch to Arabic, 404). Re-run: `cd apps/audit && bun run audit.ts [baseUrl] [outDir]`.

## What already works
- Performance: LCP 0.15–0.9 s, CLS ≈ 0, no console errors, no failed requests. Home 37 KB HTML.
- All journeys pass: filters (108 → 28 → 3), full-text search (“garrofó” → 11 dishes, 9 excerpts),
  `?q=` deep links, cooking mode + wake lock, checklist, timers, Arabic switch keeps the path, 404.
- RTL mirrors correctly; dark mode is consistent; JSON-LD valid.

## Findings (P0 = fix first)

### P0 — Information architecture & density
1. **Section pages are 52–68 phone screens long.** One card ≈ 750 px tall on mobile (image + chip +
   title + gloss + local name + 3-line summary + regions), 108 cards in one undifferentiated list.
   Browsing is impossible; the filters are the only way in.
   → Compact list layout on mobile (thumbnail left, title + gloss + region right, ~96 px), denser
   grid on desktop (4 columns, image-led, summary only on hover/focus), group by region or category
   with jump links, sort (A–Z / region / photo first), “show 24 more” progressive rendering.
2. **The recipe is buried.** Ingredients start 6.6 screens down on mobile (maqluba) after geography,
   history and town variations; the 4-person recipe is section 4 of 5.
   → Recipe page restructure: a “recipe card” above the fold (serves, active/total time if known,
   texture/category, vessel, region) + **Jump to recipe** button; tabs or an accordion for
   *Recipe · Variations · History · Sources*; sticky mini-header with the dish name and the
   Cooking-mode toggle while scrolling; ingredients as a real checklist (not a 2-column table on
   phones), method steps as large cards in cooking mode.
3. **Header costs ~20% of every phone screen** (3 rows: brand+language / Home·History·Regions·About /
   section pills) and “Home” duplicates the section switcher.
   → One row: brand · section switcher (icons + short names) · menu button (History, Regions, About,
   language, search). Hide-on-scroll-down, show-on-scroll-up. Desktop: keep one row, move language
   into the menu.
4. **“About” is the research README** (112 phone screens of index tables, titled “Arrossos d’Espanya:
   A Field Atlas of Spanish Rice”, Spain-only). → Real About page (what, who, method, sources policy,
   languages, contact/corrections) + a separate **Index of all dishes** page (A–Z, per section,
   filterable) generated from data, not from README tables.

### P1 — Consistency & clarity
5. **Cards say the same thing twice**: gloss (“Rice soup with wild partridge”) + local name + summary
   (first history sentence) + regions. → Card = image, name, gloss, region · category. Summary only on
   the recipe page / in search results.
6. **Section hero = a full phone screen before any dish** (hero, marquee, texture/category tiles, ad,
   toolbar). → Compact section header (title + one-line lede + counts) with the dishes visible on the
   first screen; keep the decorative hero only at desktop widths; drop the marquee (decorative, adds
   height, causes horizontal overflow on /thai desktop: +15 px).
7. **Category tiles duplicate the filter chips** (same options twice). → Merge: tiles become the filter.
8. **Global search is missing**: search exists only inside a section. → Header search (⌘K / “/”),
   Pagefind across all sections & languages, grouped results (dishes, regions, history).
9. **Regions nav ignores the current section**; breadcrumbs + kicker repeat the same words.
   → Regions link opens the current section’s regions; drop the duplicate kicker when crumbs exist.
10. **History index cards contain an “Enter” button inside a link** (looks like nested controls) and
    one card shows a Spanish title on the English page (“Historia del arroz en España”, content).
11. **Placeholder ad boxes are visible in production** (in-feed card-sized boxes, 300×600 sidebar on
    recipes) — they read as broken UI. → `ads.json` mode `off` until a network is live (space
    reservation can return with the real tags).
12. **Untranslated pages**: the English body under an Arabic/Spanish UI is jarring (translations in
    progress). → Show the notice once as a compact banner with a link to the English page and hide
    language-specific chrome that implies a translation exists.
13. **Footer is a dead end** (tagline only). → Footer with sections, history, regions, about,
    languages, sources/corrections link, licence/photo credits page.

### P2 — Accessibility (axe, WCAG 2.1 AA)
14. **3 104 colour-contrast failures** on 15 pages, almost all from `--ink-faint` (#9a8a78 / #8f8799 on
    card/paper ≈ 3.0–3.2 : 1) used for vessel labels, counts, credits, ad labels; plus terracotta
    kickers at 4.28 : 1. → Darken `--ink-faint` per theme to ≥ 4.5 : 1; kicker colour ≥ 4.5 : 1.
15. **Tap targets < 40 px** on mobile: section pills (≈ 33 px), brand, skip link, chips. → 44 px min.
16. **Scrollable tables not keyboard-focusable** (3 pages). → `tabindex="0"` + `role="region"` +
    `aria-label` on `.table-wrap`.
17. View-transition `InvalidStateError` on mobile when the viewport resizes mid-transition (harmless
    console noise). → Skip transitions when `matchMedia` changes / on touch devices for filters.

### P3 — Nice to have
18. Servings scaler (×2 / ×½) — quantities are structured enough in §4 tables for most dishes.
19. “Recently viewed / saved dishes” (localStorage), share button (Web Share API).
20. Photo-first cards when a section has good photo coverage; consistent aspect ratio and
    image-or-illustration treatment.
21. Region pages: map or at least a locator; region intro shorter; dishes before the long text.

## Proposed plan
- **Phase 1 (structure, P0):** new header (one row + menu + global search), compact section header,
  new card + list/grid density, grouping & sorting, recipe page restructure (recipe card, jump,
  tabs/accordion, sticky mini-header, mobile ingredient checklist), About + Index pages, ads off.
- **Phase 2 (P1/P2):** contrast tokens, tap targets, table focus, footer, untranslated-page banner,
  regions nav per section, history index cleanup, transition guards.
- **Phase 3 (P3):** servings scaler, saved dishes, share, region maps.
Each phase is re-verified with this audit script (screens per page, contrast count, journeys).
